# Independent cross-check — 15 October 2026

Read both requested research notes; checked official Microsoft/Hugging Face artifacts, Transformers v4.51.3 source, and the EACL 2027 SRW CFP. This is a source audit, not an inference run.

| Claim | Verdict | Evidence and qualification |
| --- | --- | --- |
| `microsoft/Phi-4-mini-instruct` is ungated | **UNVERIFIABLE** conclusively in this session | The [official repository](https://huggingface.co/microsoft/Phi-4-mini-instruct/tree/main) exposes files and download links without a visible access-request notice, consistent with ungated access. However, the [authoritative model API](https://huggingface.co/api/models/microsoft/Phi-4-mini-instruct) could not be retrieved; anonymous weight access was not tested. Do not treat this as evidence that it is gated. |
| Phi-4-mini-instruct is MIT-licensed | **CONFIRMED** | Microsoft's [LICENSE file](https://huggingface.co/microsoft/Phi-4-mini-instruct/blob/main/LICENSE) explicitly contains the MIT license; the [model card](https://huggingface.co/microsoft/Phi-4-mini-instruct#license) agrees. |
| It loads without `trust_remote_code` in Transformers 4.51.3 | **UNVERIFIABLE** as an executed checkpoint-load claim | Native support is independently confirmed below, but no full model load or T4/NF4 smoke test was performed. The [official card](https://huggingface.co/microsoft/Phi-4-mini-instruct#inference-with-transformers) states integration in 4.49.0 while its example still sets `trust_remote_code=True`; that example alone proves neither necessity nor successful loading without it. |
| Transformers 4.51.3 has a native loading route for this configuration | **CONFIRMED** by source inspection | The [model config](https://huggingface.co/microsoft/Phi-4-mini-instruct/raw/main/config.json) declares `model_type=phi3` and `Phi3ForCausalLM`. The [v4.51.3 causal-LM mapping](https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/models/auto/modeling_auto.py) registers that class; the [trust resolver](https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/dynamic_module_utils.py) defaults to false when native code exists, and [AutoModel dispatch](https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/models/auto/auto_factory.py) selects it. Compatibility is therefore supported by source, not runtime-tested. |
| Phi has a system-capable chat template | **CONFIRMED** | Its [tokenizer configuration](https://huggingface.co/microsoft/Phi-4-mini-instruct/raw/main/tokenizer_config.json) serializes supplied roles, including `system`, with role delimiters and an end marker; it also has explicit system/tool handling. |
| EACL 2027 SRW mentorship deadline is 6 November 2026 | **CONFIRMED** | The [official CFP](https://2027.eacl.org/calls/srw/#important-dates) lists this date; its mentorship section repeats it. Deadline: 23:59 UTC−12 (AoE). |
| EACL 2027 SRW submission deadline is 15 December 2026 | **CONFIRMED** | The [official CFP](https://2027.eacl.org/calls/srw/#important-dates) gives this date specifically for direct workshop submissions, at 23:59 UTC−12 (AoE). |

**CONTRADICTED — adjacent model-note claim:** Phi does not insert a default system prompt when one is absent. Its [current template](https://huggingface.co/microsoft/Phi-4-mini-instruct/raw/main/tokenizer_config.json) only serializes supplied messages and appends the generation/EOS marker. Passing the fixed English system instruction remains appropriate for experimental consistency.

**Venue caveat:** The [CFP](https://2027.eacl.org/calls/srw/) really prints 22 December **2027** for ARR commitment, after the March conference. Treat a correction to 2026 as unverified; this inconsistency does not alter the two explicitly confirmed direct-track dates.

**Second-model judgment:** No clearly better replacement established under the existing different-family, similar-size, Transformers 4.51.3 constraints. Retain Phi provisionally pending the load/access checks. [Granite-3.3-2B-Instruct](https://huggingface.co/ibm-granite/granite-3.3-2b-instruct) is a smaller Apache-2.0 fallback, but its supported-language list also omits Hindi; no evidence here establishes superior E/R/C performance. [SmolLM3's current config](https://huggingface.co/HuggingFaceTB/SmolLM3-3B/blob/main/config.json) requires the `smollm3` architecture, so it does not offer the same native 4.51.3 route.

Remaining verification: obtain the API's `gated` field and run the pinned checkpoint with `trust_remote_code=False` in the intended 4.51.3/T4/NF4 environment before describing successful loading as confirmed. No weights were downloaded or experiments run in this audit.
