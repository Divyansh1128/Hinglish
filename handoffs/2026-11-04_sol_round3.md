## Required DEV sanity after an interruption

**The old behavior violated the reporting requirement in §5/§12.** A valid training finish alone did not establish
that its required 120-generation DEV report existed. Re-running Train could advance to the next adapter, including
finishing the ninth adapter without its report.

Train now drains incomplete DEV reports **before consulting the next training action and after a valid training
run**. It also does this when every training slot is already settled. The engine resumes its existing journal;
stale evaluation locks still require explicit `RECOVER_STALE_LOCK` confirmation. Completed, validating reports are
skipped without regeneration. The helper holds the training-root writer lock while evaluating and the notebook
uses its existing **subprocess** evaluator so model/GPU memory is released before the next training process.
The valid-adapter set includes valid adapters in subsequently replaced triplets, so those reports are not lost.

Freeze now refuses any missing/invalid required DEV export and freezes its bytes. Report completeness is checked
against frozen DEV data, registered config/source/environment, the exact adapter, checksums and all 120 resolved
generations; an output filename or COMPLETE status alone is insufficient. This requires reporting, never a DEV
score threshold or any checkpoint/arm/rerun selection. The runbook's interruption row and Train notebook prose
were updated.

Regressions execute interruption after seven DEV generations, refusal of an unconfirmed stale lock, confirmed
resume to 120 with the original seven journal files byte-identical, an unchanged attempt log, no reload of an
already complete report, refusal when adapter nine's report is absent, and DEV ZIP hash enforcement after freeze.
The executable notebook control test also proves a pending DEV error prevents the next training start.

## Stale-writer failure-class decision

**Confirm Claude's decision.** Recovery should retain a numerical/protocol failure already recorded by the
attempt's own report. That is an established failure awaiting its finish event, rather than an otherwise unknown
abandoned run. Converting it to infrastructure would erase the known §3/Amendment-1 halting condition and authorize
an impermissible retry. An interrupted attempt without such a recorded halting failure closes as infrastructure.
The report is preserved and the recovery is logged. The new
`WriterOwnershipTests.test_confirmed_recovery_preserves_both_recorded_halting_failure_classes` verifies both
classes through full confirmed recovery, lock release and subsequent `StudyHalted` refusal. No registration text
or failure/retry policy was changed.
