# Correctness review

1. **P1 — Nested ZIP expansion bypasses the total-memory bound.** `paper_analysis/build_tables.py:139-141` retains every expanded inner archive in `runs`, while `paper_analysis/safezip.py:51,73` resets its byte budget for each archive. Concrete failing input: an outer ZIP containing 100 `*_results.zip` members, each containing four DEFLATE-compressed, zero-filled 256 MiB files. Every member and individual archive satisfies the current limits; the outer archive expands to roughly 100 MiB of inner ZIP bytes, but expansion retains 100 GiB before `load_run()` can even reject missing checksums. This can exhaust memory despite the 1 GiB safety bound. Confirmed with a bounded reproduction: temporarily patching the limits in memory to 1,024 bytes/member and 2,048 bytes/archive, four inner ZIPs containing four 500-byte files each pass `_expand_inputs()` and retain 8,000 bytes; the outer expanded size is only 1,720 bytes. Apply a cumulative expansion budget or process and release inner archives sequentially.

2. **P2 — Valid source IDs can become duplicate self-translation IDs.** `exploratory/self_translate.py:58` appends `-ST` to R/C IDs without checking the unchanged E IDs. Concrete failing input: take `test1_pilot/fixtures/demo_dataset.json`, set the first family's E ID to `source-R-ST` and R ID to `source-R`, and provide nonempty translations for all R/C IDs. The source passes `hinglish_pilot.data.validate(..., 'demo')`; `second_stage_dataset()` returns E and R with the identical ID `source-R-ST`. Any subsequent ID-indexed joining or evaluation conflates the source E item and translated R item. Validate uniqueness across the entire resulting dataset before returning it.

3. **P2 — Run folder names can collide with top-level output files and crash after writing outputs.** `paper_analysis/build_tables.py:465-472` reserves only other run slugs, although `paper_analysis/build_tables.py:544,556` also writes `per_rendering.csv` and `README.md` at the output root. Concrete failing input: rename an otherwise valid exported ZIP to `README.md_results.zip` or `per_rendering.csv_results.zip`, then run the CLI with a fresh `--out` directory and `--no-figures`. Both reproduce an uncaught `IsADirectoryError`: the corresponding run directory occupies the path needed by the top-level file. Partial output remains and prevents an immediate retry. Reserve these output filenames when allocating slugs.

4. **P2 — Corrupt compressed members escape ZIP error handling.** `paper_analysis/safezip.py:69` omits `zlib.error`, which `ZipExtFile.read()` raises for invalid DEFLATE streams. Concrete failing input: create a ZIP_DEFLATED member `file.txt` containing `b'hello' * 100`, then replace the first compressed payload byte (offset `30 + filename_length + extra_length` in this single-member ZIP) with `0xff`. `read_zip()` raises `zlib.error: Error -3 while decompressing data: invalid block type`, rather than `UnsafeArchive`; the CLI consequently exits through an uncaught traceback instead of its documented input-rejection path. Catch and translate decompression errors.

5. **P2 — Malformed prediction headers crash outside the run-validation handler.** `paper_analysis/build_tables.py:300` indexes CSV fields without validating their presence, and its call at `paper_analysis/build_tables.py:498` is outside the exception handler for malformed run content. Concrete failing input: replace `predictions.csv` in an otherwise valid results ZIP with `b'wrong_header\nfoo\n'`, updating `checksums.sha256` accordingly. Calling `main([... , '--no-figures'])` reproduces an uncaught `KeyError('rendering_id')` instead of returning input-rejection exit code 1. Validate required CSV headers and include consistency validation within the guarded validation phase.
